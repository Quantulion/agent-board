# agent-board, план 5: скилл — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Tasks that write skill text MUST load superpowers:writing-skills first and follow it (including its testing discipline).

**Goal:** Скилл `agent-board`, который пользователь Claude Code или Codex запускает после любого скилла планирования: он настраивает проект вопросами, принимает план или готовые задачи, раскладывает их в граф на странице согласования, передаёт обсуждение агенту проекта и поднимает доску — а также поднимает доску существующего проекта по просьбе «подними доску проекта X». Плюс упаковка в плагин и закрытие хвостов плана 4.

**Architecture:** Скилл — тонкий оркестратор поверх CLI `agent-board` (все записи — через `init`, `config set`, `add-task`, `deps`, `update --rule-violations-json`, `stage`, `serve`). Сам скилл ничего не реализует в коде проекта и не держит состояние: всё в доске. Обёртка `scripts/agent-board` внутри скилла запускает пакет из того же репозитория, поэтому установка — это установка плагина/копирование каталога скилла, без pip. Тексты скилла на английском; общение с пользователем — на его языке.

**Tech Stack:** Markdown (SKILL.md + references/), POSIX sh-обёртка, Python 3.9 stdlib (доработки сервера), Claude Code plugin manifest (`.claude-plugin/plugin.json`, `marketplace.json`), Codex skills (`~/.codex/skills/<name>/SKILL.md` или `.agents/skills/` в репозитории; frontmatter `name`, `description`).

**Spec:** `docs/superpowers/specs/2026-11-04-agent-board-design.md` (разделы «Процесс» 0–4, «Настройки проекта», «Агент проекта», «Хранение»); хвосты — `docs/superpowers/plans/2026-11-05-roadmap.md` («Хвосты плана 4»).

## Global Constraints

- Скилл ничего не пушит, не заводит задачи в трекере, не переводит стадии дальше `decomposition` и не одобряет — всё это действия пользователя на доске.
- Скилл не пишет `project.json` и файлы доски напрямую — только через CLI/API (валидация, блокировка).
- Секреты не спрашиваются в чате и не записываются нигде: скилл просит указать имя переменной окружения или путь к файлу.
- Тексты скилла — на английском, кратко и императивно (superpowers:writing-skills); вопросы пользователю и итоговые сообщения — на языке пользователя.
- Работает в Claude Code и Codex: никаких инструментов, специфичных для одного харнесса, в основном потоке; различия — в `references/harness-claude.md` / `references/harness-codex.md`.
- Рантайм доски — без новых зависимостей.

## Review Focus

1. Пользователь даёт план от writing-plans → скилл создаёт проект, задачи с зависимостями и критериями, нарушения правил, бриф агента проекта, ссылки — и даёт ссылку на страницу разбивки; на доске нет агентов задач до утверждения (Task 5, Task 6).
2. Повторный запуск в том же проекте не дублирует задачи и не затирает настройки, а предлагает продолжить (Task 4).
3. Пользователь называет секрет прямо в чате → скилл не записывает его и просит переменную окружения/файл (Task 3).
4. Сервер уже запущен / не запущен / запущен со старой версией → скилл корректно подключается или поднимает его (Task 2).
5. Скилл в Codex: те же шаги без инструментов Claude Code (Task 6).

## Структура файлов

```

skills/agent-board/
  SKILL.md                          # основной поток (англ.)
  scripts/agent-board               # sh-обёртка: python3 -m agent_board с PYTHONPATH на board/ этого репозитория
  references/setup.md               # вопросы настройки и маппинг ответов в config set
  references/intake.md              # разбор плана / готовых задач в граф
  references/decomposition-rules.md # проверка правил, формат rule_violations
  references/harness-claude.md      # фоновый serve, уведомления (Monitor), установка
  references/harness-codex.md       # то же для Codex
  references/resume.md              # «подними доску проекта X», статусы, частые проблемы
scripts/install-codex.sh            # копирует/линкует скилл в ~/.codex/skills
board/agent_board/…                 # доработки сервера (Task 1)
board/tests/skill/                  # тесты сценариев скилла (Task 6)
```

### Task 1: Хвосты плана 4

**Files:** `board.py`, `config.py`, `server.py`, `tracker.py`, `review.py`/`runner.py`, tests

- [ ] Проверка конфига: проверки ФС и `git rev-parse` — до взятия блокировки доски и только для изменившихся `repos`; под блокировкой — перечитать, слить, структурные проверки; полные проверки — для изменённых полей, структурные — для итога (старые проекты не блокируют правку настроек). Тесты: медленный `git` (монкипатч) не держит блокировку; старый конфиг с устаревшим полем допускает правку другого поля.
- [ ] `config set` с неизвестным полем (в т.ч. `to_dict`) → 400 (сверка с полями dataclass). Тест.
- [ ] `add-task` только от `user` (агенты задач и агент проекта — через `propose`); промпт агента задачи: «нужна новая задача — напиши агенту проекта (`say _project`)». Тесты.
- [ ] Синхронизация трекера: проекты в `done` опрашиваются ещё 24 ч после перехода, затем нет; проекты синхронизируются параллельно ограниченным пулом (≤ 4 потока), зависший проект не задерживает остальные. Тесты на поддельных часах.
- [ ] Устаревший `ship_command` при загрузке переносится в `ship.command` (если `ship` пуст) с записью в журнал. Тест.
- [ ] Данные ревью crit задачи удаляются через 7 дней после `done`/`cancelled`; лог ревью и отправки обрезается до последних 1 МБ при открытии нового раунда/отправки. Тесты.

### Task 4: SKILL.md — основной поток

**Files:** Create `skills/agent-board/SKILL.md`, `references/intake.md`, `references/decomposition-rules.md`, `references/resume.md`

- [ ] Загрузить superpowers:writing-skills и следовать ему: description отвечает «когда использовать» (после скилла планирования; «разложи план на задачи и запусти агентов»; «подними доску проекта X»), без пересказа процесса; тело — короткий чек-лист с ссылками на references.
- [ ] Поток (SKILL.md):
  1. `agent-board status` → сервер и проекты. Просьба «подними доску X» → `references/resume.md`.
  2. Проект: новый (`init`) или существующий (показать стадию/число задач; на стадии decomposition — предложить дополнить, иначе — открыть доску и закончить) (Review Focus 2).
  3. Настройка — `references/setup.md` (пропустить то, что уже настроено).
  4. Вход: путь к плану/спеке, текст, или готовые задачи/ключи трекера — `references/intake.md`: извлечь задачи (заголовок, что сделать, критерий готовности, репозиторий, тип, оценка), зависимости, проверить граф (`agent-board add-task` по порядку, ошибки цикла — исправить), не дублировать уже существующие (сверка по заголовку/ключу).
  5. Правила декомпозиции — `references/decomposition-rules.md`: проверить каждую задачу против правил проекта, записать нарушения (`update --rule-violations-json`, от лица user), не исправлять молча — предложить исправление в общем треде.
  6. Бриф агента проекта (`config set project_brief`): цель, ключевые решения плана, ссылки (`config set links` — план, спека, макеты).
  7. `agent-board serve --detach` → ссылка на страницу разбивки `…#/p/<slug>/decomposition`; объяснить: комментарии к задачам читает агент проекта, «Утвердить разбивку» запускает работу; дальше терминал не нужен.
  8. Харнесс-специфичное (фоновые процессы, уведомления) — `references/harness-*.md`.
- [ ] Красные флаги в SKILL.md: не реализовывать задачи самому; не запускать агентов задач; не утверждать разбивку; не заводить задачи в трекере; не просить секреты.
