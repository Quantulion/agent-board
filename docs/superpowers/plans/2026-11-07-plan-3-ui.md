# agent-board, план 3: интерфейс — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Живая доска в браузере на реальном API: доска с колонками и «Ждут вас», карточка задачи со вкладками, граф, тред «Проект» с предложениями, новая задача, страница согласования разбивки — всё с обновлением в реальном времени.

**Architecture:** Сервер отдаёт статическое одностраничное приложение из `board/agent_board/static/` (vanilla JS ES-модули, без сборки и зависимостей). Состояние — снимок `GET /api/p/<slug>/state` плюс поток событий SSE; на событие клиент перечитывает снимок (с объединением частых событий) и точечно перерисовывает изменившиеся части, не трогая открытую карточку, её вкладку, прокрутку и черновик сообщения. Визуальный язык, структура и поведение — по утверждённым макетам `docs/design/mockups/` (вариант A).

**Tech Stack:** HTML/CSS/vanilla JS (ES2020 modules), Python stdlib на сервере. Для разработки: `node --test` для чистых JS-модулей и dev-only смоук-тест на puppeteer в `ui-tests/` (не часть рантайма).

**Spec:** `docs/superpowers/specs/2026-11-04-agent-board-design.md` (разделы «Доска», «Утверждённый дизайн», «Статусы и переходы», «Разбивка и согласование»); макеты `docs/design/mockups/{board,card,decomposition,index}.html`; хвосты плана 2 — `docs/superpowers/plans/2026-11-05-roadmap.md`.

## Global Constraints

- Рантайм без зависимостей и без сборки: файлы в `static/` отдаются как есть; никаких внешних запросов (шрифты — системный стек; доска должна работать офлайн).
- Визуальный паритет с макетами A: те же цвета-токены, светлая/тёмная тема (prefers-color-scheme + переключатель), чипы по размеру содержимого, узлы графа не переполняются, вкладки карточки меняют только содержимое панели (без перерисовки и повторной анимации).
- Любой текст от агентов и пользователя выводится только экранированным (`textContent` или функция `esc`); разметка сообщений — минимальный безопасный markdown (абзацы, `код`, блоки кода, ссылки http(s) с `rel="noopener noreferrer"`), без `innerHTML` сырых строк.
- Интерфейс на русском (язык из `config.language` используется для будущей локализации; строки — в одном модуле `i18n.js`).
- Обновление в реальном времени через SSE с переподключением по `Last-Event-ID`; при переподключении — перечитать снимок.
- Перерисовка не сбрасывает: открытую карточку и её вкладку, ширину панели, прокрутку колонок и треда, введённый черновик, раскрытые «Контекст».
- Агенты задач запускаются только на стадии `work`; до неё (разбивка, трекер) раннер не стартует агентов задач.

## Review Focus

1. Агент пишет в резюме или тред `<img src=x onerror=alert(1)>` или `javascript:`-ссылку → отображается как текст, ничего не выполняется (Task 3, Task 5).
2. Сервер перезапустили, пока вкладка открыта → вкладка переподключается сама, пропущенные изменения появляются без перезагрузки (Task 3, Task 8).
3. Пока пользователь пишет ответ в треде, приходят десятки событий → черновик, фокус и прокрутка не теряются (Task 5).
4. Доска на 60 задач и частые события → интерфейс не подвисает: события объединяются, перерисовываются только изменившиеся карточки (Task 3, Task 4).
5. Перетаскивание в недопустимый статус (агентский запрет, «Заблокирована») → понятная ошибка в тосте, карточка возвращается на место (Task 4).

## Структура файлов

```
board/agent_board/static/
  index.html          # оболочка: шапка, контейнеры видов, подключение main.js и app.css
  app.css             # токены, темы, компоненты (из макета A)
  js/main.js          # маршрутизация (#/p/<slug>, #/p/<slug>/decomposition, #/), запуск
  js/api.js           # fetch к API (cookie-токен), ошибки → исключения с текстом сервера
  js/store.js         # снимок + SSE, объединение событий, подписки видов; чистые функции разбора
  js/dom.js           # h(), esc(), safeMarkdown(), бережная перерисовка списка (keyed)
  js/i18n.js          # строки интерфейса, подписи статусов
  js/board.js         # доска: шапка, «Ждут вас», колонки, карточки, DnD, фильтры, тосты
  js/card.js          # выезжающая карточка: вкладки Обзор/Тред/Ревью/Изменения
  js/graph.js         # раскладка графа (чистая функция) и SVG-рендер
  js/project.js       # панель «Проект»: тред и предложения; модалка «Новая задача»
  js/decomposition.js # страница согласования разбивки
board/tests/js/       # node --test для store.js, dom.js, graph.js (чистые функции)
ui-tests/             # dev-only: package.json (puppeteer), smoke.mjs
```

### Task 2: API для интерфейса

**Files:** Modify `server.py`, `board.py`, `config.py`, `model.py`; Tests `test_server.py`, `test_board.py`

**Interfaces — Produces:**
- `GET /api/p/<slug>/tasks/<key>/diff` → `{"base": str, "files": [str], "diff": str, "truncated": bool}` (из `worktree.changed_files`/`diff` относительно `base_branch`; до 400 КБ текста, дальше `truncated: true`); без worktree → `{"files": [], "diff": "", "base": null}`.
- `ProjectConfig.links: list[dict] = []` — `{"title", "href"}` (http(s) или путь к локальному файлу); snapshot отдаёт `links`. Локальный путь открывается через `GET /api/p/<slug>/file?path=<path>` только если путь внутри каталога проекта, его репозиториев или их worktree (иначе 403); отдаётся как text/plain или text/html (html — с `Content-Security-Policy: sandbox`).
- `Task.rule_violations: list[dict] = []` — `{"rule", "text"}`; пишут `project_agent` и `user` через update (не runner-поле). Snapshot — как есть.
- Snapshot задачи дополнительно: `thread_size: int`, `last_message: {author, text(≤200), at} | null`, `open_questions: int`.
- `POST /api/p/<slug>/tasks` от `user` — уже есть; ответ дополняется `key`.

- [ ] **Step 1–4:** тесты на каждый пункт (включая выход за разрешённые каталоги для `file` → 403, html с CSP, обрезку диффа) → реализация → PASS.
