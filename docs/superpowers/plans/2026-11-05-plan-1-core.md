# agent-board, план 1: ядро — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Локальный демон доски: модель задач, постоянное хранилище, граф зависимостей, правила переходов статусов с реакциями-событиями, предложения агента проекта, HTTP API с SSE и консольная утилита для агентов.

**Architecture:** Один процесс-демон (`python3 -m agent_board serve`) — единственный писатель состояния; все изменения идут через `Board` (сервисный слой) под одной блокировкой и превращаются в события журнала. HTTP API и SSE отдают состояние браузеру; CLI ходит в тот же API (адрес и токен — из файла обнаружения сервера). Реакции на переходы (разблокировать, разбудить, остановить агента) в этом плане только порождают события; исполняет их план 2.

**Tech Stack:** Python ≥ 3.9, только стандартная библиотека в рантайме (`http.server.ThreadingHTTPServer`, `json`, `dataclasses`, `threading`, `argparse`, `urllib`). Тесты — pytest.

**Spec:** `docs/superpowers/specs/2026-11-04-agent-board-design.md`; дорожная карта — `docs/superpowers/plans/2026-11-05-roadmap.md`.

## Global Constraints

- Рантайм — только стандартная библиотека Python, совместимость с 3.9: `from __future__ import annotations` в каждом модуле, без `match`, без `tomllib`, без `X | Y` в рантайм-аннотациях вне строк.
- Корень хранилища: `$AGENT_BOARD_HOME`, по умолчанию `~/.agent-board`. Проекты — `<root>/projects/<slug>/`. Никаких временных папок.
- Статусы (id → подпись): `not_started` Не начата, `blocked` Заблокирована, `in_progress` В работе, `waiting_answer` Ждёт ответа, `queued` Ждёт очереди, `in_review` На ревью, `approved` Одобрена, `sent` Отправлена, `done` Готово, `cancelled` Отменена.
- Цепочки веток включены по умолчанию (`chains: true`): зависимость считается выполненной в `approved`, `sent`, `done`; при `chains: false` — только в `done`.
- Агент проекта не меняет граф сам: новые задачи, изменения зависимостей и отмена от него — только предложения, применяются действием пользователя.
- Сервер слушает только `127.0.0.1`; каждый запрос API требует токен (заголовок `X-Board-Token` или cookie `board_token`); запросы с чужим `Origin` отклоняются.
- Ничего не пишет в трекер и git в этом плане.

## Review Focus

1. Много агентов одновременно пишут через CLI → ни одно обновление не теряется (одна блокировка в `Board`, тест с потоками — Task 6).
2. Новая задача, правка зависимостей или предложение создают цикл или ссылаются на несуществующую задачу → понятная ошибка 400, состояние не меняется (Task 3, Task 5).
3. Процесс убит посреди записи → файлы задач остаются валидным JSON (атомарная запись через временный файл и `os.replace` — Task 2).
4. Браузерная вкладка с чужого сайта шлёт POST на localhost → 403 (токен и `Origin` — Task 7).
5. Браузер переподключился к SSE после рестарта сервера → получает пропущенные события по `Last-Event-ID` (Task 7).

### Task 3: Граф зависимостей

**Files:**
- Create: `board/agent_board/graph.py`
- Test: `board/tests/test_graph.py`

**Interfaces:**
- Consumes: `Task`, `Status`, `DEP_SATISFIED_*`.
- Produces:
  - `open_deps(task: Task, tasks: dict[str, Task], chains: bool) -> list[str]` — зависимости, ещё не выполненные; отменённые зависимости не считаются.
  - `display_status(task, tasks, chains) -> Status` — `BLOCKED`, если хранимый статус `NOT_STARTED` и есть `open_deps` или `external_blocker`; иначе хранимый.
  - `ready_tasks(tasks, chains) -> list[str]` — `NOT_STARTED`, без открытых зависимостей и внешнего блокера, отсортированы по ключу.
  - `find_cycle(tasks: dict[str, Task]) -> list[str] | None` — путь цикла или `None`.
  - `validate_deps(key: str, deps: list[str], tasks) -> None` — `ValueError` с текстом на русском при неизвестной задаче, зависимости от себя или цикле.
  - `base_for(task, tasks, chains, default_base: str) -> tuple[str, list[str]]` — `(база, ветки_для_вливания)`: без цепочек или без невлитых зависимостей → `(default_base, [])`; одна незавершённая (`approved`/`sent`) зависимость → `(её branch, [])`; несколько → `(default_base, [их branch])`.
  - `critical_path(tasks) -> list[str]` — самый длинный путь по сумме `estimate` (None = 1), без отменённых.
  - `dependents(key, tasks) -> list[str]` — прямые зависимые.

### Task 4: Board — переходы, реакции, вопросы, треды

**Files:**
- Create: `board/agent_board/board.py`
- Test: `board/tests/test_board.py`

**Interfaces:**
- Consumes: Tasks 1–3.
- Produces `class Board(store: ProjectStore)` — все публичные методы под `self._lock = threading.RLock()`, каждое изменение пишет события через `store.append_event` и возвращает их списком. Время — через инжектируемый `clock: Callable[[], str]` (ISO-8601 UTC), по умолчанию системные часы.
  - `snapshot() -> dict` — `{"config": ..., "tasks": [task.to_dict() + {"display_status", "open_deps"}], "proposals": [...], "last_seq": int}`.
  - `add_task(task: Task, actor: str) -> list[Event]` — `validate_deps`; ключ уникален (иначе `ValueError`); событие `task_added`; если задача сразу готова — плюс `agent_wake {key, reason: "ready"}`.
  - `transition(key: str, to: Status, actor: str) -> list[Event]` — `actor ∈ {"user", "agent", "tracker"}`; событие `status_changed {key, from, to, actor}`; реакции:
    - новый статус делает зависимости выполненными → для каждой ставшей готовой зависимой задачи `task_unblocked {key}` + `agent_wake {key, reason: "unblocked"}`;
    - пользователь или трекер вернули задачу в `in_progress` из `in_review`/`approved`/`sent`/`done` → `agent_wake {key, reason: "returned", from}`;
    - `cancelled` → `agent_stop {key}`, ключ удаляется из `deps` всех задач (событие `deps_changed` на каждую), затем проверка разблокировки;
    - агенту (`actor="agent"`) нельзя ставить `done`, `sent`, `cancelled` → `PermissionError`.
  - `update_task(key, actor, **fields) -> list[Event]` — только поля из белого списка (`summary, todo, changed_files, review, worktree, branch, base_branch, session_id, report, tracker_key, tracker_url, external_blocker, description, done_when, title, estimate`); событие `task_updated {key, fields: [...]}`.
  - `set_deps(key, deps, actor) -> list[Event]` — `validate_deps`; `deps_changed`; проверка разблокировки.
  - `ask(key, question: Question) -> list[Event]` — добавляет вопрос, ставит `waiting_answer` (actor agent), события `question_asked`, `status_changed`.
  - `answer(key, qid, choice: str | None, comment: str) -> list[Event]` — пишет `answer`, сообщение пользователя в тред с `question_id`, событие `question_answered` + `agent_wake {key, reason: "answer"}`; если открытых вопросов не осталось и статус `waiting_answer` → `in_progress` (actor system).
  - `post_message(thread: str, author: str, text: str) -> list[Event]` — `thread` = ключ задачи или `"_project"`; событие `message_posted`; сообщение от `user` → `agent_wake {key или "_project", reason: "message"}`; от `project_agent` в тред задачи → тоже будит агента задачи; `unread += 1` для сообщений не от пользователя, `mark_read(thread)` обнуляет.
