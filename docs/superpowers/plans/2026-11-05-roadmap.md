# agent-board — дорожная карта планов

Спека: `docs/superpowers/specs/2026-11-04-agent-board-design.md`. Макеты: `docs/design/mockups/`.

Спека охватывает несколько подсистем, поэтому реализация разбита на пять планов. Каждый даёт работающий, тестируемый результат; следующий план пишется после завершения предыдущего, опираясь на его фактические интерфейсы.

| # | План | Результат | Зависит от |
|---|---|---|---|
| 1 | Ядро: модель, хранилище, граф, переходы, HTTP API, CLI | Демон доски с API и SSE, консольная утилита; всё состояние и правила переходов покрыты тестами. Агентов ещё нет: реакции сервера выражены событиями | — |
| 2 | Исполнение: адаптеры харнессов (Claude Code, Codex), запуск/продолжение сессий, worktree и цепочки веток, общие ресурсы с арендой, агент проекта, прерванные ходы | Сервер сам запускает агентов на разблокированные задачи, будит их сообщениями, агент проекта отвечает в треде «Проект» | 1 |
| 3 | Интерфейс: перенос утверждённых макетов на живые данные (доска, карточка со вкладками, граф, тред «Проект», «Ждут вас», страница разбивки) | Доска в браузере на реальном API с live-обновлением | 1 (2 — для живых агентов) |
| 4 | Интеграции: трекеры (Jira, GitHub Issues), фоновое чтение статусов, ревью (crit / без инструмента), команда «Отправить в ревью» | Задачи заводятся в трекере, статусы подтягиваются, ревью и отправка работают по кнопкам | 1, 2 |
| 5 | Скилл: SKILL.md, настройка проекта вопросами, вход (план / задачи), разбивка и согласование, платформенные справочники, упаковка плагина | Скилл, который пользователь запускает после любого скилла планирования | 1–4 |

Стек (решение builder'а, спека оставила его открытым): Python ≥ 3.9 только на стандартной библиотеке в рантайме (есть на macOS «из коробки», ставится везде без Node-тулчейна), pytest — только для разработки. UI — статический HTML/CSS/vanilla JS, как в макетах.

## Хвосты плана 1 (взять в план 2)

- **Порт на macOS:** из-за SO_REUSEADDR сервер занимает `127.0.0.1:8737`, даже если другое приложение слушает `0.0.0.0:8737`. Перед bind в цикле портов по умолчанию пропускать порт, на котором уже кто-то отвечает.
- `BoardServer.start()`: действия после bind (поток, запись `server.json`) — внутри try с освобождением блокировки; существующий `<home>/token` приводить к правам 0600.
- `base_for` молча пропускает зависимость в `approved`/`sent` без ветки — раннер должен решать явно (иначе worktree без кода зависимости); дедуп веток.
- Ребейз зависимых задач при изменении ветки зависимости (реопен, вливание) — реакция раннера.
- Исключение в `on_event` обрывает операцию Board на середине — подписчики раннера не должны бросать.
- `ask` на `done`/`sent`/`cancelled` переоткрывает задачу; повтор перехода в тот же статус порождает событие.
- Актор самоназванный (`AGENT_BOARD_ACTOR`): выдавать агентам токены, привязанные к актору и задаче.
- План 3: после установки cookie по `/?token=` делать редирект на `/`, чтобы токен не оставался в адресной строке.
- В тексте плана 1 сигнатура `update_task(key, actor, **fields)` устарела: теперь `update_task(key, actor, fields: dict)`.
